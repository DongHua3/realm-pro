## 📖 项目简介

**Realm Pro** 是一套专为 Linux VPS 设计的高性能网络中转一键管理脚本。基于纯 Rust 编写的顶级流量中转引擎 [zhboner/realm](https://github.com/zhboner/realm)，具备**极低资源开销**（内存 <15MB）、**零 GC 延迟**、**全双工高并发**等特性。

本脚本彻底解决了传统一键脚本“无法在菜单中删除规则”、“误设沙箱权限导致 80/443 特权端口启动报错”、“国内 VPS 下载超时”、“无输入校验易导致配置崩溃”等诸多痛点，提供生产级的规则增删查改与运维诊断工具。

## ✨ 核心亮点

- ⚡ **全局极简快捷键**：安装后在终端输入 **`re`** 即可呼出全功能交互面板（亦兼容 `realm`）。
- 📋 **完整规则生命周期 (CRUD)**：
  - 结构化表格清晰罗列所有监听与转发节点。
  - 基于 `rules.d/` 原子化单文件架构，增删改查不污染其他规则，删除时同步移除防火墙放行规则。
  - 自动备份配置文件，规则增删改失败时自动回滚，配置异常可随时用备份恢复。
- 🛡️ **全端口特权绑定与安全加固**：
  - 修复原版 Systemd 沙箱权限缺陷，正确赋予 `CAP_NET_BIND_SERVICE`，完美支持 **80 / 443 / 53** 等特权端口。
  - 下载二进制直连官方 API 执行 **SHA-256 完整性哈希校验**，无法获取官方哈希时强制中止安装，防范第三方镜像投毒。
  - 自动适配 SELinux 安全上下文（支持 CentOS / Rocky / Fedora）。
- 🌐 **双栈与协议增强**：
  - 智能识别与清洗 IPv4 / IPv6，自动格式化补齐 `[...]` 方括号。
  - 支持 **HAProxy PROXY Protocol (v1/v2)**，中转节点可无缝传递客户端真实源 IP。
- 🚀 **生产级系统调优**：
  - 预设 `LimitNOFILE=1048576`，解除高并发场景下的句柄瓶颈。
  - 配置 `Restart=on-failure` 与 `RestartSec=3s` 守护进程高可用。
- 🌏 **双网络镜像加速**：内置 GitHub 官方直连及多组高速 CDN 镜像代理（如 `ghproxy`），解决大陆 VPS 拉取 Releases 失败问题。
- 🔧 **集成综合诊断体检 (Doctor)**：内置全链路 TCP 握手延时测试、连通性探测以及 Journald 实时日志滚动追踪。
- 💻 **命令行直接传参**：支持不进入交互菜单直接执行 `re add`、`re ls`、`re doctor` 等 CLI 指令。

## 🚀 快速开始

### 1. 一键安装命令

登录你的中转机 VPS，在终端中以 root 权限执行以下命令即可：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DongHua3/realm-pro/main/realm.sh)
```

> **提示（大陆 / 访问受限 VPS 加速源）**：若无法直接连接 GitHub，可使用内置镜像代理：
> ```bash
> bash <(curl -fsSL https://ghproxy.net/https://raw.githubusercontent.com/DongHua3/realm-pro/main/realm.sh)
> ```
>
> **提示（Alpine Linux）**：Alpine 默认不带 bash，请先执行 `apk add bash curl` 再运行上方一键安装命令。

### 2. 唤出管理菜单

安装完成后，在终端任意路径下直接输入：

```bash
re
```

## 📚 详细使用教程

### 🎯 架构拓扑说明

```text
[ 客户端 (手机/电脑) ] 
       │
       ▼ (优质链路，如三网优化线路 / 国内 BGP)
[ 中转 VPS (安装 Realm) ] ──── 监听端口 (如: 6666)
       │
       ▼ (公网专线 / 国际骨干高速链路)
[ 落地 VPS (节点/服务器) ] ──── 实际业务端口 (如: 443)
```

---

### 步骤一：安装与初始化

1. 登录中转机（VPS A）终端，以 `root` 用户运行一键安装命令；
2. 安装过程中选择下载镜像源（境外 VPS 选 `1. 官方直连`，大陆 VPS 选 `2. ghproxy 加速`）；
3. 脚本会自动下载二进制、校验 SHA-256、配置 Systemd / OpenRC 服务并放行基础运行环境。

---

### 步骤二：添加端口转发规则

输入 `re` 唤出菜单，选择 **`[1] 添加转发规则`**（亦可直接运行 `re add`）：

1. **输入中转机本地监听端口**：例如 `6666`（客户端将连接中转机的这个端口）；
2. **选择监听地址类型**：例如 `0.0.0.0`（全部 IPv4）或 `[::]`（IPv4+IPv6 双栈）；
3. **输入落地机 IP 或域名**：例如 `1.2.3.4` 或 `hk.example.com`（若是 IPv6 地址直接粘贴即可，脚本会自动识别补充方括号）；
4. **输入落地机目标端口**：例如 `443`（落地机上对应服务实际监听的端口）；
5. **选择是否启用 PROXY Protocol**：
   - **绝大多数普通中转**：选 `1. 不开启`（默认）；
   - **落地节点配置了 PROXY 协议接收真实 IP**：选 `2. 开启 v2`；
6. **输入备注说明**：例如 `香港BGP中转-美西落地`；
7. 脚本将自动写入独立的 `rules.d/` 规则、放行中转机防火墙、重启 Realm 服务并验证连通性。

---

### 步骤三：修改客户端配置

在中转规则添加成功后，需要将你手机/电脑客户端中的配置进行对应修改：

| 客户端配置项 | 原直连配置（落地机） | 经中转机转发后的配置 |
| :--- | :--- | :--- |
| **服务器地址 (Address/Host)** | 填写落地机 IP (`1.2.3.4`) | **改为中转机 IP (`114.114.114.114`)** |
| **端口 (Port)** | 填写落地机端口 (`443`) | **改为中转机监听端口 (`6666`)** |
| **UUID / 密码 / 协议类型** | 保持不变 | 保持不变 |
| **SNI / 伪装域名 / 公钥** | `your-domain.com` | **必须保持原落地机的伪装域名不变** |

> ⚠️ **关键注意点**：如果你的节点开启了 TLS / Reality / WS 伪装，**客户端里的 SNI / Peer / 伪装域名千万不要改成中转机 IP**，必须依然填写落地机原本的域名或公钥！

---

### 步骤四：规则查看、删除与排障

- **查看当前所有规则**：在菜单中按 `2` 或在终端运行 `re ls`，将以清晰表格显示所有转发列表、协议类型与备注。
- **修改已有规则**：在菜单中按 `3` 或在终端运行 `re edit`，输入端口号即可原地更新落地目标或备注。
- **删除无用规则**：在菜单中按 `4` 或在终端运行 `re del`，输入对应规则的 `端口号` 即可秒级移除，同时脚本会自动关闭对应防火墙端口。
- **综合体检诊断**：在菜单中按 `10` 或在终端运行 `re doctor`，一键审计所有规则监听状态、落地 DNS 解析与 TCP 握手延时。
- **测试单点连通性**：在菜单中按 `11`，输入落地机 IP 和端口，脚本将进行 TCP 握手延时探测，排查落地机网络是否通畅。

## 🎯 深度实战场景（直击 VPS 核心痛点）

### 场景 1：廉价大盘机 / 普通线路小鸡“晚高峰救砖拉满”
- **用户痛点**：买了非常便宜的欧美大带宽/大盘鸡（如 RackNerd、ColoCrossing、Netcup、OVH 等），配置高、流量多，但直连路由极差，晚高峰三大运营商丢包率高达 30%~50%，油管看视频卡在 360P 或直接断流。
- **Realm 解法**：买一台带三网高端优化线路（电信 CN2 GIA / 联通 9929 / 移动 CMIN2）的超低价 NAT 小鸡（如几块钱一个月）作为入口中转机，通过 Realm 转发流量到落地大盘机。经过优化链路中转后，晚高峰丢包降至接近 0%，轻松跑满 4K/8K 视频流。

---

### 场景 2：免花钱换 IP，0 成本“复活”被墙的落地小鸡
- **用户痛点**：落地 VPS 的 IP 遭受 GFW 阻断（TCP 握手被 RST、443 端口无法连接），商家更换 IP 动辄收费 $3~$5，甚至很多特价机商家不支持更换 IP。
- **Realm 解法**：境外服务器之间互相访问完全正常、不受影响。只要中转机 IP 正常可用，在中转机上通过 Realm 将流量转发到被封锁的落地机，客户端直接连接中转机，**无需花费一分钱即可满血复活被封小鸡**。

---

### 场景 3：解决家宽 / 校园网无 IPv6 访问纯 IPv6 廉价小鸡
- **用户痛点**：购买了市面上几块钱一年的超廉价纯 IPv6 VPS（如 Wap、ByteVirt、Hax、Scaleway Stardust），但自己家里的宽带、公司网络或手机流量没有分配公网 IPv6 地址，根本无法直连。
- **Realm 解法**：找一台具有双栈（IPv4+IPv6）的中转机运行本脚本，添加一条规则：监听中转机的一个 IPv4 端口，目标地址填纯 IPv6（如 `2400:3200::1:443`，脚本会自动格式化）。客户端只需连接中转机的 IPv4 端口，即可丝滑访问纯 IPv6 落地节点。

---

### 场景 4：隐藏核心服务器真实源站 IP（防扫端口、防 DDOS 攻击）
- **用户痛点**：个人自建核心服务、私有节点或游戏私服，直接在公网暴露真实 IP 容易被全网扫描封禁，或者遭到恶意 DDOS 导致主服务器瘫痪。
- **Realm 解法**：前端使用廉价的 NAT 小鸡对外提供连接端口，真实落地源站的防火墙只放行中转机 IP 的入站连接。即使前端中转机被攻击或阻断，换一台几块钱的小鸡重新配置只需 1 分钟，保护核心源站稳如泰山。

---

### 场景 5：外服联机游戏 / P2P 串流 NAT 穿透极速加速
- **用户痛点**：Steam / APEX / CS2 / 任天堂 Switch 外服联机游戏或异地 Moonlight/Sunshine 串流对 UDP 丢包和 NAT 类型极其敏感，直连经常 NAT Type Strict 或连接超时。
- **Realm 解法**：Realm 基于 Rust 编写并深度优化了 Linux 批量 UDP 传输（`recvmmsg`/`sendmmsg`），CPU 和内存消耗几乎为零，Full Cone NAT 转发能力极强，延迟抖动极小，能提供媲美商业加速器的游戏中转加速体验。

> 💡 **重要安全提示**：Realm 是纯透明的高性能端口转发工具，中转机与落地机之间不会进行二次加密。因此在落地端搭建服务时，**请务必使用自带加密的协议（如 VLESS+Reality / Shadowsocks / Hysteria 2 / HTTPS / SSH 等）**，切勿直接裸传明文敏感流量！

## ❓ 常见问题 (FAQ)

### Q1: 转发配置完成后，客户端连接不通怎么办？
请按以下顺序依次排查：
1. **中转机本地防火墙**：虽然脚本会自动放行系统防火墙，但如果使用腾讯云、阿里云、AWS、甲骨文云，务必进入**云厂商网页控制台 ➔ 安全组 (Security Group)**，放行中转机对应的入站端口。
2. **全链路综合体检**：在终端输入 `re doctor`，检查本地端口是否监听中，以及中转机到落地机的 TCP 延时。
3. **证书与 SNI 校验**：如果节点开启了 TLS，确认客户端中的 `SNI / 伪装域名` 仍然填写的是落地机的域名，而不是中转机 IP。

### Q2: 为什么中转机内存占用这么低？
`zhboner/realm` 由纯 Rust 开发，没有 Go 语言的 GC 垃圾回收开销，异步并发机制极为高效。日常稳定占用仅 **5MB ~ 15MB** 内存，极适合 256MB/512MB 的低配 VPS。

### Q3: 如何备份或迁移配置？
所有中转规则均保存在 `/etc/realm/rules.d/` 目录中。
若需要更换 VPS：
1. 在终端运行 `re backup`，将生成的备份文件复制到新 VPS；
2. 在新 VPS 上安装本脚本；
3. 将备份文件解压覆盖到新机器的 `/etc/realm/` 并运行 `re restart` 即可一键还原。
