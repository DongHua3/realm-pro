## 📖 项目简介

**Realm Pro** 是一套专为 Linux VPS 设计的高性能网络中转一键管理脚本。基于纯 Rust 编写的顶级流量中转引擎 [zhboner/realm](https://github.com/zhboner/realm)，具备**极低资源开销**（内存 <15MB）、**零 GC 延迟**、**全双工高并发**等特性。

本脚本彻底解决了传统一键脚本“无法在菜单中删除规则”、“误设沙箱权限导致 80/443 特权端口启动报错”、“国内 VPS 下载超时”、“无输入校验易导致配置崩溃”等诸多痛点，提供生产级的规则增删查改与运维诊断工具。

## ✨ 核心亮点

- ⚡ **全局极简快捷键**：安装后在终端输入 **`re`** 即可唤出全功能交互面板（亦兼容 `realm`）。
- 📋 **完整规则生命周期 (CRUD)**：
  - 结构化表格清晰罗列所有监听与转发节点。
  - 支持按规则序号精确定位并删除，删除时同步移除防火墙放行规则。
  - 自动备份配置文件并支持语法异常时一键回滚。
- 🛡️ **全端口特权绑定**：修复原版 Systemd 沙箱权限缺陷，正确赋予 `CAP_NET_BIND_SERVICE`，完美支持 **80 / 443 / 53** 等特权端口。
- 🌐 **双栈与协议增强**：
  - 智能识别 IPv4 / IPv6 并自动格式化（自动补充 `[...]` 括号）。
  - 支持 **HAProxy PROXY Protocol (v1/v2)**，中转节点可无缝传递客户端真实源 IP。
- 🚀 **生产级系统调优**：
  - 预设 `LimitNOFILE=1048576` 与 `LimitNPROC=512`，解除高并发场景下的句柄瓶颈。
  - 配置 `Restart=on-failure` 与 `RestartSec=3s` 守护进程高可用。
- 🌏 **双网络镜像加速**：内置 GitHub 官方直连及多组高速 CDN 镜像代理（如 `ghproxy`），解决大陆 VPS 拉取 Releases 失败问题。
- 🔧 **集成网络诊断工具**：内置 TCP 握手延时测试、连通性探测以及实时日志滚动追踪。
- 💻 **命令行直接传参**：支持不进入交互菜单直接执行 `re add`、`re ls`、`re restart` 等 CLI 指令。

## 🚀 快速开始

### 1. 一键安装命令

登录你的中转机 VPS，在终端中执行以下命令即可：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DongHua3/realm-pro/main/realm.sh)
```

> **提示（大陆 / 访问受限 VPS 加速源）**：若无法直接连接 GitHub，可使用内置镜像代理：
> ```bash
> bash <(curl -fsSL https://ghproxy.net/https://raw.githubusercontent.com/DongHua3/realm-pro/main/realm.sh)
> ```

### 2. 唤出管理菜单

安装完成后，在终端任意路径下直接输入：

```bash
re
```

## 📚 详细使用教程

### 🎯 架构原理说明

在典型的网络加速架构中：
```text
[ 你的电脑 / 手机 ] 
       │
       ▼ (低延迟/优质线路，如国内 BGP / 优质中转机)
[ 中转 VPS (安装 Realm) ] ──── 监听端口 (如: 1234)
       │
       ▼ (内网专线 / 国际公网加速链路)
[ 落地 VPS (节点/服务器) ] ──── 监听端口 (如: 443)
```

---

### 步骤一：安装与初始化

1. 登录中转机（VPS A）终端，以 `root` 用户运行一键安装命令；
2. 安装过程中选择下载镜像源（境外 VPS 选 `1. 官方直连`，大陆 VPS 选 `2. ghproxy 加速`）；
3. 脚本会自动下载二进制、配置 Systemd 服务并放行基础环境。

---

### 步骤二：添加端口转发规则

输入 `re` 唤出菜单，选择 **`[1] 添加转发规则`**：

1. **输入中转机本地监听端口**：例如 `6666`（客户端将连接中转机的这个端口）；
2. **输入落地机 IP 或域名**：例如 `1.2.3.4` 或 `hk.example.com`（如果是 IPv6 地址直接粘贴即可，脚本会自动识别补充方括号）；
3. **输入落地机目标端口**：例如 `443`（落地机上对应服务实际监听的端口）；
4. **选择是否启用 PROXY Protocol**：
   - **绝大多数普通中转**：选 `1. 不开启`（默认）；
   - **落地节点配置了 PROXY 协议接收真实 IP**：选 `2. 开启 v2`；
5. **输入备注说明**：例如 `香港BGP中转-美西落地`；
6. 脚本将自动写入配置、放行中转机防火墙、重启 Realm 服务并验证连通性。

---

### 步骤三：修改客户端配置

在中转规则添加成功后，需要将你手机/电脑客户端中的配置进行微调：

| 客户端配置项 | 原直连配置（落地机） | 经中转机转发后的配置 |
| :--- | :--- | :--- |
| **服务器地址 (Address/Host)** | 填写落地机 IP (`1.2.3.4`) | **改为中转机 IP (`114.114.114.114`)** |
| **端口 (Port)** | 填写落地机端口 (`443`) | **改为中转机监听端口 (`6666`)** |
| **UUID / 密码 / 传输协议** | 保持不变 | 保持不变 |
| **SNI / 伪装域名 / 证书** | `your-domain.com` | **必须保持原落地机的伪装域名不变** |

> ⚠️ **关键注意点**：如果你的节点开启了 TLS / Reality / WS 伪装，**客户端里的 SNI / Peer / 伪装域名千万不要改成中转机 IP**，必须依然填写落地机原本的域名或公钥！

---

### 步骤四：规则查看与管理

- **查看当前所有规则**：在菜单中按 `2` 或在终端运行 `re ls`，将以清晰表格显示所有转发列表、协议类型与备注。
- **删除无用规则**：在菜单中按 `3` 或在终端运行 `re del`，输入对应规则的 `ID 序号` 即可秒级移除，同时脚本会自动关闭对应防火墙端口。
- **测试连通性**：在菜单中按 `9`，输入落地机 IP 和端口，脚本将进行 TCP 握手延时探测，排查落地机是否通畅。

## 💡 典型实战场景

### 场景 1：Hysteria 2 / TUIC / 游戏加速（全双工 UDP 极速中转）
- **特点**：Hysteria 2 和 TUIC 基于 UDP 协议构建。
- **操作**：直接使用本脚本添加规则即可。Realm 默认开启了 `use_udp = true`，自动支持 TCP+UDP 批量并发转发，无需额外配置。

### 场景 2：拯救纯 IPv6 落地小鸡（IPv4 中转机 ➔ IPv6 落地机）
- **特点**：很多极低价格的 VPS 只有 IPv6 地址，在很多仅支持 IPv4 的网络环境下无法直连。
- **操作**：
  1. 使用一台双栈（拥有 IPv4）的中转机运行本脚本；
  2. 添加规则时，落地机地址直接输入纯 IPv6（如 `2400:3200::1`）；
  3. 脚本会自动转换为 `[2400:3200::1]:443`；
  4. 你的客户端只需连接中转机的 IPv4 端口，即可丝滑访问纯 IPv6 落地节点！

### 场景 3：PROXY Protocol 传递真实客户端 IP
- **特点**：普通中转会导致落地机看到的连接 IP 全部是中转机 IP，影响风控与日志审计。
- **操作**：
  1. 落地端（如 Xray / V2Ray / Nginx）开启 `acceptProxyProtocol: true`；
  2. 在本脚本添加规则时，第 5 步选择 `2. 开启 PROXY Protocol v2`；
  3. 客户端连接中转机，落地机即可精准识别客户端的真实地理位置与 IP。

## ⌨️ 快捷命令汇总

除了交互式菜单，脚本还支持在命令行中直接传参执行，适合脚本调用或自动化运维：

| 快捷指令 | 说明 |
| :--- | :--- |
| **`re`** | 打开交互式管理控制面板（主菜单） |
| **`re list`** / **`re ls`** | 快速查看当前所有转发规则表格 |
| **`re add`** | 快速启动添加转发规则流程 |
| **`re del`** / **`re rm`** | 快速启动删除指定规则流程 |
| **`re status`** | 查看 Realm 服务的详细运行状态 |
| **`re restart`** | 重启 Realm 服务并刷新所有配置 |
| **`re start`** | 启动 Realm 服务 |
| **`re stop`** | 停止 Realm 服务 |
| **`re log`** | 实时滚动查看 Realm 运行日志 |
| **`re update`** | 检查并更新 Realm 核心程序至最新版 |
| **`re uninstall`** | 彻底卸载 Realm 服务与相关配置文件 |

| 评估维度 | 常见第三方 Realm 脚本 | **Realm Pro (本项目)** |
| :--- | :--- | :--- |
| **规则管理** | 仅支持单向追加写入，**无法在终端查看和删除** | **完整 CRUD**：表格化展示、按序号精确删除、自动查重 |
| **特权端口 (<1024)** | 误设 `DynamicUser=true`，**80/443 端口启动报错** | **原生支持**：配置系统特权绑定，全端口任意监听 |
| **输入校验** | 毫无校验，输错空格或字母**导致已有中转全部瘫痪** | **严格校验**：端口 1~65535 检测、占用检测、失败自动回滚 |
| **IPv6 支持** | 拼接语法错误，导致 TOML 解析失败 | **智能规范化**：自动识别 IPv6 格式并补充方括号 |
| **PROXY 协议** | 不支持 | **支持**：可选注入 PROXY Protocol (v1/v2) 传递真实源 IP |
| **系统兼容性** | 仅支持 Debian/Ubuntu + UFW | **全发行版自适应**：Debian/Ubuntu/CentOS/Rocky/Alma/Alpine/Arch |
| **防火墙联动** | 仅适配 UFW | **全自动适配**：UFW / Firewalld / iptables 智能识别与放行 |
| **并发调优** | 默认 systemd 参数 | **预设百万级句柄限制**（`LimitNOFILE=1048576`） |
| **国内机加速** | 仅直连 GitHub，经常超时拉取失败 | **内置多组高速 GitHub 镜像源**，一键切换 |

## ❓ 常见问题 (FAQ)

### Q1: 转发配置完成后，客户端连接不通怎么办？
请按以下顺序依次排查：
1. **中转机本地防火墙**：虽然脚本会自动放行系统防火墙，但如果使用腾讯云、阿里云、AWS、甲骨文云，务必进入**云厂商网页控制台 ➔ 安全组 (Security Group)**，放行中转机对应的入站端口。
2. **落地机连通性**：在菜单中选择 `[9] 目标网络连通性诊断`，测试中转机是否能连通落地机的 IP 与端口。
3. **证书与 SNI 校验**：如果节点开启了 TLS，确认客户端中的 `SNI / 伪装域名` 仍然填写的是落地机的域名，而不是中转机 IP。

### Q2: 为什么中转机内存占用这么低？
`zhboner/realm` 由纯 Rust 开发，没有 Go 语言的 GC 垃圾回收开销，异步并发机制极为高效。日常稳定占用仅 **5MB ~ 15MB** 内存，极适合 256MB/512MB 的低配 VPS。

### Q3: 如何备份或迁移配置？
所有中转规则均保存在 `/etc/realm/config.toml` 文件中。
若需要更换 VPS：
1. 复制原机器的 `/etc/realm/config.toml`；
2. 在新 VPS 上安装本脚本；
3. 将文件覆盖到新 VPS 的 `/etc/realm/config.toml` 并运行 `re restart` 即可一键还原。
